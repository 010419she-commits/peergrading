# 在现有仓库中进行双 Agent 协作

0.3 增加真实文件协作。作者读取仓库后编辑文件，审查者读取同一工作目录与每轮差异；需要继续修改时，两位 Agent 交换角色。原有「生成文字 / 代码成果」方式保留。

## 开始使用

1. 安装 Git，并安装、登录 Claude Code 或 Codex CLI。两位都必须选择这两类 CLI 中的一种；可以选同一种工具但使用不同人设。纯 API 模型和剪贴板中转暂不支持直接编辑仓库。
2. 在原仓库提交已有改动，或自行使用 `git stash` 保存。仓库至少需要一个提交；未提交和未跟踪文件会阻止启动。程序不会清理、重置或覆盖它们。
3. 打开桌面工作台，选择「修改现有 Git 仓库」，选择目录并点「检查仓库」。开发者可通过 `npm run dev` 在本机工作台输入绝对路径。公网生产网站不会接受服务器仓库路径。
4. 描述任务，选择 A、B，可填写每行一条的验证命令，例如 `npm test`、`npm run build`、`python3 -m unittest`、`cargo test`。命令按参数数组执行，支持引号包围含空格的参数，不支持管道、重定向、变量展开或多条命令用 `&&` 拼接。Windows 路径建议用正斜杠并为含空格的路径加引号。
5. 点击开始。任务从原仓库 HEAD 创建独立工作目录与 `codex/peergrading-*` 分支。界面显示讨论、每轮版本、验证结果和可下载的 Git 补丁。仓库自身的 AGENTS.md 等说明仍由相应 CLI 读取。

## 工作目录与验证

隔离目录和清单位于本次会话的 `repository/` 下，清单包含源仓库、任务分支、工作目录、各轮提交和验证结果。源码在这个目录中真实修改，每一版有对应 Git 提交和补丁；目录不会在任务结束时删除。单个仓库同时只允许一个协作任务。审查和讨论阶段使用只读权限，发现意外改动会终止并保留现场。

验证命令在工作目录中运行，不使用操作系统容器隔离；仅运行你信任的项目。工作目录只包含已提交文件，不会复制原目录里的 `.env`、忽略文件或 `node_modules`。依赖、环境变量和凭证需要你按项目要求准备，可以将安装命令作为第一条验证命令，例如 `npm ci`。每条命令默认最多运行两分钟。未配置测试时，只能说明模型审查通过，不代表执行验证通过。

Git worktree 用于隔离文件和分支改动，并非进程安全沙箱。Claude 作者允许文件读取和编辑，测试由程序运行；Codex 使用其工作目录写入沙箱。两位 Agent 不会被要求推送、自动合并或删除原目录。子模块、Git LFS、特殊 Git 过滤器及需要外部服务的仓库可能需要额外准备；无法保证任意语言、任意构建环境无需配置即可运行。

## 取回成果

结束后在右侧查看任务分支和目录，打开每一版补丁审阅。确认满意后，在原仓库执行 `git merge <界面显示的任务分支>`。若只要部分提交，可自行 cherry-pick 或应用补丁。合并前正常处理本地新改动与冲突；程序不会自动替你处理原目录冲突。

停止、失败或达到轮数上限时都会保留任务工作目录与已完成提交，界面区分已通过、达到上限、已取消和失败。最大轮数后的版本不会未经审查就被标成成功。测试失败不能被 Agent 的「通过」结论覆盖。

任务目录无需保留后，可按 Git 正常流程执行 `git worktree remove <任务目录>`，再自行删除对应任务分支。仍有未提交工作时应先检查和保存，避免使用强制删除。

## 开发验证

运行 `npm test` 验证临时仓库中的角色轮换、真实写文件、原目录隔离、取消、失败及通知验签等行为；测试不调用付费模型或真实支付渠道。`npm run bundle` 同时生成桌面服务与本地托管的信用卡结账 SDK 包。真实 CLI 授权、商户审核和多系统安装仍须在各自环境完成。
