接入说明

本地模型需要以 SCAN_MODELS=1 启用模型扫描，并启动 Ollama 或 LM Studio 服务。

本地模型用于文字与代码成果协作；直接修改现有 Git 仓库使用 Kimi Code、Codex 或 Claude Code CLI。

与云端协作时，任务、成果和相关讨论会发送至所选服务。使用前请确认服务配置。

云端辅助加速

减少整体等待，
不夸大为 token 级加速。

加速发生在任务调度和应用层缓存：并行准备独立审查、复用完全匹配的结果。它不改变模型生成 token 的速度，也不承诺供应商内部共享计算。

01 / PARALLEL

任务级并行预审

预审只读取绑定的完整快照。采纳前重新核对当前快照 SHA-256；失配、失败或过期结果会丢弃并回退，不会套用到新版本。

02 / EXACT CACHE

精确缓存

缓存键覆盖快照内容、模型、角色和审查上下文等全部有效输入。只有完全匹配且完整性校验通过才复用，不用相似文本猜测命中。

这里减少的是串行等待和完全相同的重复审查，不减少必要审查、测试或通过条件。界面只显示启动、采用、回退、缓存命中和重叠时间等状态，不展示候选正文或 reasoning。

仓库协作

从你已有的工程，
接着往下做。

修复一个 bug、补齐一项功能，或者整理一段代码。不必新建项目，把任务交给两个已经安装并登录的命令行 Agent。

软件从当前提交创建独立分支与 worktree。两个 Agent 在其中轮流工作，你的原工作区保持原样，最后由你决定是否合并。

  1. 01 / EDIT

    改的是实际工程

    读取仓库里的代码，编辑真实文件。仓库模式支持 Kimi Code、Codex 或 Claude Code CLI，沿用你已经登录的账号。

  2. 02 / REVIEW

    看差异，再提意见

    审查者读取累计代码差异，指出具体问题并与作者讨论；需要修改时交换角色，继续下一版。

  3. 03 / VERIFY

    检查与提交都有记录

    按你设定的命令运行检查，失败时不会标记通过。每轮保留提交、补丁、检查结果与协作对话。

流程

把任务交给他们，
把决定留给你。

从选择仓库到审阅补丁，整个协作循环在桌面软件中完成。你可以设定轮次上限，也可以随时停止。

  1. 01

    选择现有仓库

    选择本机上工作区干净、已有提交的 Git 仓库。选好两个 Agent，写下任务与测试命令。

  2. 02

    轮流修改与审查

    A 完成初版并运行检查；B 读取差异、审查并讨论，再接手修改；A 继续审查。通过审查和检查，或到达轮次上限时结束。

  3. 03

    审阅后合并

    查看每轮差异、检查结果和提交，下载补丁或打开任务 worktree。确认后自行合并任务分支。

需要本机安装 Git，以及已登录的 Kimi Code、Codex 或 Claude Code CLI。Agent 的订阅或 API 用量由对应服务商计费。
